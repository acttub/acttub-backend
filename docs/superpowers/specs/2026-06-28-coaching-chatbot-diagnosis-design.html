SOMA-152 코칭 챗봇형 진단 설계

작성일: 2026-06-28 · 대상 브랜치: feature/SOMA-152-chatbot-acting-diagnosis

목표

코칭 생성 직후 최종 평가를 내리지 않고, AI가 배우와 챗봇 형태로 대화하며 연기 의도와 장면 상황을 구체화한 뒤 최종 진단을 생성한다. 첫 영상 업로드 응답은 초기 분석 컨텍스트와 첫 질문을 반환한다. 이후 사용자는 메시지 API로 답변하고, AI는 충분한 맥락이 모일 때까지 다음 질문을 생성한다.

결정 사항

  • 초기 응답POST /api/v1/coachings는 QUESTION_READY와 첫 질문을 반환한다.
  • 대화 APIPOST /api/v1/coachings/{coachingId}/messages가 사용자 답변 저장과 다음 AI 질문 생성을 담당한다.
  • 턴 정책대화 종료 판단은 AI가 하되 min-turns=3, max-turns=7로 제한한다.
  • 최소 턴1~2번째 답변 후에는 AI가 충분하다고 판단해도 다음 질문을 생성한다.
  • 최대 턴7번째 답변 후에는 AI 판단과 무관하게 READY_FOR_DIAGNOSIS로 전환한다.
  • 최종 진단READY_FOR_DIAGNOSIS 상태에서 POST /api/v1/coachings/{coachingId}/diagnosis를 호출해 최종 진단을 생성한다.
  • 영상 재분석 없음메시지와 최종 진단 단계에서는 영상을 다시 업로드하거나 다시 분석하지 않는다.

범위

포함

  • 상태 QUESTION_READY, IN_CONVERSATION, READY_FOR_DIAGNOSIS 추가 또는 정리
  • 대화 턴 저장 모델 추가
  • 대화 정책 설정 app.coaching.conversation.min-turns=3, max-turns=7 추가
  • 메시지 API 추가
  • Gemini 대화 지속/종료 판단 프롬프트 추가
  • 누적 대화 컨텍스트 기반 최종 진단 API 수정
  • API 문서, 통합 테스트, 도메인 테스트, AI 파서 테스트 갱신

제외

  • 실시간 스트리밍 응답
  • 사용자가 대화 턴 수를 요청마다 직접 지정하는 기능
  • 대화 중 영상 재업로드 또는 영상 재분석
  • 코칭 결과 조회 API 신설
  • 비동기 작업 큐 도입

상태 흐름

ANALYZING
  -> QUESTION_READY        // 초기 분석과 첫 질문 생성 완료
  -> IN_CONVERSATION       // 답변을 받았고 다음 질문이 남아 있음
  -> READY_FOR_DIAGNOSIS   // 최소 3턴 이후 충분하거나 최대 7턴 도달
  -> COMPLETED             // 최종 진단 생성 완료
  -> FAILED                // 영상 저장, AI 분석, 대화, 진단 실패
상태 의미 허용 API
QUESTION_READY 첫 AI 질문이 준비된 상태 POST /messages
IN_CONVERSATION 다음 질문이 남아 있어 사용자 답변을 기다리는 상태 POST /messages
READY_FOR_DIAGNOSIS 최종 진단에 필요한 대화 맥락이 충분한 상태 POST /diagnosis
COMPLETED 최종 진단 완료 POST /evaluation

사용자 흐름

  1. 사용자가 영상, 장르, 상황, 인물 설정, 선택 서브텍스트를 업로드한다.
  2. 서버는 영상을 저장하고 AI 초기 분석을 요청한다.
  3. AI는 대본, 초기 분석, 측정 가능한 관찰 신호, 주관적 진단 가설, 첫 질문을 반환한다.
  4. 서버는 첫 질문을 assistant 메시지로 저장하고 QUESTION_READY를 응답한다.
  5. 사용자가 현재 질문에 답하면 프론트는 POST /messages로 답변을 제출한다.
  6. 서버는 답변을 user 메시지로 저장하고, 누적 대화와 정책을 AI에 전달한다.
  7. 1~2턴이면 반드시 다음 질문을 생성한다.
  8. 3~6턴이면 AI가 충분성을 판단해 다음 질문 또는 READY_FOR_DIAGNOSIS를 응답한다.
  9. 7턴이면 강제로 READY_FOR_DIAGNOSIS를 응답한다.
  10. 프론트가 POST /diagnosis를 호출하면 서버는 누적 대화 요약과 구체화된 상황/의도로 최종 진단을 생성한다.

POST/api/v1/coachings

연기 영상을 업로드하고 초기 분석 컨텍스트와 첫 질문을 생성한다.

{
  "data": {
    "coachingId": "1",
    "status": "QUESTION_READY",
    "dialogue": {
      "question": "이 장면에서 상대에게 가장 들키고 싶지 않았던 감정은 무엇이었나요?"
    },
    "conversation": {
      "turnIndex": 0,
      "minTurns": 3,
      "maxTurns": 7,
      "diagnosisReady": false
    },
    "context": {
      "transcript": "안녕. 오랜만이네.",
      "analysis": "시선 회피와 짧은 호흡이 먼저 관찰됩니다.",
      "measurableSignals": [
        {
          "name": "pause_before_first_line",
          "value": 2.0,
          "unit": "초",
          "evidence": "첫 대사 전 약 2초간 정지"
        }
      ],
      "diagnosticHypothesis": "숨기려는 감정의 이유가 아직 덜 구체화되어 있습니다."
    }
  }
}

POST/api/v1/coachings/{coachingId}/messages

현재 AI 질문에 대한 사용자 답변을 제출한다. 응답은 다음 질문 또는 진단 준비 상태다.

요청

{
  "answer": "미련을 들키면 내가 아직 약한 사람처럼 보일까 봐 숨겼습니다."
}

다음 질문 응답

{
  "data": {
    "coachingId": "1",
    "status": "IN_CONVERSATION",
    "dialogue": {
      "question": "그 약해 보이고 싶지 않은 마음은 상대를 밀어내려는 선택인가요, 다시 붙잡고 싶은 마음을 숨기는 선택인가요?"
    },
    "conversation": {
      "turnIndex": 1,
      "minTurns": 3,
      "maxTurns": 7,
      "diagnosisReady": false,
      "reason": "최소 3턴 전이므로 의도 구체화를 계속합니다."
    }
  }
}

진단 준비 응답

{
  "data": {
    "coachingId": "1",
    "status": "READY_FOR_DIAGNOSIS",
    "conversation": {
      "turnIndex": 4,
      "minTurns": 3,
      "maxTurns": 7,
      "diagnosisReady": true,
      "summary": "사용자는 미련을 숨기는 이유가 상대에게 약해 보이고 싶지 않기 때문이라고 구체화했습니다."
    },
    "refinedContext": {
      "refinedSituation": "재회한 상대 앞에서 흔들리는 마음을 들키지 않으려는 상황",
      "refinedIntent": "미련을 숨기며 평정심을 유지해 주도권을 잃지 않으려는 의도"
    }
  }
}

POST/api/v1/coachings/{coachingId}/diagnosis

READY_FOR_DIAGNOSIS 상태의 코칭에 대해 최종 진단을 생성한다. 요청 본문은 받지 않으며, 저장된 초기 컨텍스트와 누적 대화 메시지를 사용한다. 

{
  "data": {
    "coachingId": "1",
    "status": "COMPLETED",
    "refinedContext": {
      "refinedSituation": "재회한 상대 앞에서 흔들리는 마음을 들키지 않으려는 상황",
      "refinedIntent": "미련을 숨기며 평정심을 유지해 주도권을 잃지 않으려는 의도"
    },
    "result": {
      "overallStrength": {
        "text": "감정을 바로 드러내지 않고 버티는 선택이 장면의 긴장을 살렸습니다."
      },
      "feedbackCards": [
        {
          "order": 1,
          "title": "첫 대사 전 목표를 더 선명히 잡아보세요",
          "observations": [
            {
              "timecode": "0:00-0:15",
              "text": "첫 대사 전 시선이 흔들리고 호흡이 짧아졌습니다."
            }
          ],
          "cause": "숨기는 이유보다 긴장이 먼저 몸에 올라와 의도가 덜 보였습니다.",
          "practiceSteps": [
            "첫 대사 전 '약해 보이지 않는다'는 목표를 한 문장으로 속으로 말하기",
            "상대 눈을 1초 본 뒤 대사를 시작하기"
          ],
          "expectedEffect": "감정 억제가 단순 긴장이 아니라 인물의 선택으로 읽힙니다."
        }
      ]
    }
  }
}

데이터 모델

  • coaching: 초기 입력, 영상 정보, 초기 분석 컨텍스트, 상태, 대화 요약, 구체화된 상황/의도, 최종 진단을 저장한다.
  • coaching_conversation_messages: coaching_id, role, turn_index, content, created_at을 저장한다.
  • 초기 질문은 ASSISTANT 메시지의 turn_index=1로 저장한다.
  • 사용자 답변은 같은 turn_index의 USER 메시지로 저장한다.
  • 다음 질문은 다음 turn_index의 ASSISTANT 메시지로 저장한다.

AI 계약

초기 분석

  • 입력: 영상 파일, 장르, 상황, 인물 설정, 서브텍스트
  • 출력: 첫 질문, transcript, analysis, measurableSignals, diagnosticHypothesis

대화 진행

  • 입력: 초기 컨텍스트, 전체 메시지 히스토리, minTurns=3, maxTurns=7, 현재 턴
  • 출력: diagnosisReady, nextQuestion, summary, refinedSituation, refinedIntent, reason
  • 서버는 3턴 전에는 diagnosisReady=true를 무시하고 다음 질문을 요구한다.
  • 서버는 7턴 도달 시 diagnosisReady=false여도 진단 준비 상태로 전환한다.

최종 진단

  • 입력: 초기 컨텍스트, 전체 메시지 히스토리, 대화 요약, 구체화된 상황/의도
  • 출력: 최종 CoachFeedback
  • 프롬프트는 영상에서 확인되지 않은 사실, 시간대, 대사를 새로 만들지 않도록 제한한다.

오류 처리

조건 HTTP code
메시지 요청 본문이 없거나 답변이 비어 있음 400 INVALID_MESSAGE_REQUEST
QUESTION_READY 또는 IN_CONVERSATION이 아닌 코칭에 메시지 제출 409 COACHING_NOT_READY_FOR_MESSAGE
READY_FOR_DIAGNOSIS가 아닌 코칭에 최종 진단 요청 409 COACHING_NOT_READY_FOR_DIAGNOSIS
AI 대화 질문 생성 실패 502 AI_CONVERSATION_FAILED
AI 대화 질문 생성 타임아웃 504 AI_CONVERSATION_TIMEOUT

테스트 전략

  • 코칭 생성 응답이 QUESTION_READY, 첫 질문, 초기 컨텍스트, 대화 정책을 반환하는지 검증한다.
  • 1~2번째 메시지 후에는 AI가 충분하다고 해도 IN_CONVERSATION이 유지되는지 검증한다.
  • 3번째 이후 AI가 충분하다고 하면 READY_FOR_DIAGNOSIS로 전환되는지 검증한다.
  • 7번째 메시지 후에는 AI 판단과 무관하게 READY_FOR_DIAGNOSIS로 전환되는지 검증한다.
  • READY_FOR_DIAGNOSIS 상태에서만 최종 진단 API가 성공하는지 검증한다.
  • 대화 메시지가 순서와 역할을 보존해 저장되는지 검증한다.

호환성 메모

기존 1회 답변 방식의 POST /api/v1/coachings/{coachingId}/diagnosis 요청 본문 answer는 메시지 API로 이동한다. 프론트는 업로드 응답의 첫 질문을 표시한 뒤, 사용자 답변마다 /messages를 호출하고, READY_FOR_DIAGNOSIS가 반환되면 /diagnosis를 호출해야 한다.
