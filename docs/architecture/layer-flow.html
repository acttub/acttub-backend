Acttub Backend Layer Flow

현재 코드는 코칭 기능을 presentation, application, domain, infrastructure, global로 나누고 application이 port를 통해 외부 구현을 사용하도록 정리된 구조입니다.

핵심 결론

Controller → Service → Domain 흐름을 유지하면서, AI 분석, 영상 저장, DB 저장은 application.port 뒤로 숨깁니다. command/result는 application.model에 있고, DTO 변환은 presentation이 맡습니다.

실용적 Spring 구조

application → Spring

서비스가 @Service, @Transactional을 사용하고, 평가 중복 처리에서 DataIntegrityViolationException을 압니다.

프레임워크 관심사가 application에 일부 존재

domain → JPA

Coaching 엔티티가 @Entity, @Table을 압니다.

저장 기술 어노테이션이 domain에 있음

엄격한 목표

순수 application service와 JPA entity를 분리하고, Spring 예외를 infrastructure 안에서 application 예외로 바꿀 수 있습니다.

이번 변경 범위에서는 제외

현재 집중한 개선

application → presentation.dto, application → infrastructure, application → HTTP status 의존 제거

  • OpenApiConfig: Swagger/OpenAPI 설정
지금 기준

VideoStorage, CoachingAnalyzer, repository port는 application.port에 있고, command/result 값은 application.model에 있습니다. CoachingResponse, EvaluationResponse는 presentation에 남아 controller가 변환합니다.

클린하게 만들 때의 분리 기준

application이 모르게 만든 것

CoachingResponse, EvaluationResponse 같은 API DTO와 infrastructure 패키지의 JPA repository 구현체.

application이 알아도 되는 것

Coaching 같은 domain 모델, 그리고 VideoStorage, CoachingAnalyzer처럼 application이 직접 정의한 port.

infrastructure의 역할

application이 정한 port를 실제 기술로 구현합니다. 로컬 파일, MySQL/JPA, Gemini 연결은 여기로 갑니다.

presentation의 역할

HTTP request를 application command로 바꾸고, application result를 response DTO로 바꿉니다.

global의 역할

공통 응답 envelope, 전역 예외 처리, Swagger/OpenAPI처럼 특정 기능 하나에 묶이지 않는 API 공통 관심사를 둡니다.
