PR #3 Codex 리뷰 대응 정리

Codex 리뷰에서 나온 지적을 기준으로, 무엇이 문제였고 어떤 방식으로 수정했는지 코드 예시와 함께 정리한 문서입니다. 마지막 JPA annotation 분리 항목은 이번 PR 범위에서 의도적으로 제외했습니다.

13 총 리뷰 항목
12 코드로 처리한 항목
1 의도적으로 미처리한 항목
pass ./gradlew test 통과

핵심 변경 흐름

  • 런타임 파일 저장 폴더와 Java 패키지 이름 충돌을 분리했습니다.
  • 운영 환경에서 가짜 AI 분석기가 기본 Bean으로 등록되지 않게 막았습니다.
  • focus axes JSON 컬럼 정규화 과정에서 중복/null 값이 배포를 막지 않도록 했습니다.
  • application 계층이 Spring Web, HTTP status, API response 세부사항을 직접 알지 않게 분리했습니다.
  • API 실패 응답이 일관되게 envelope 형식으로 내려가도록 예외 핸들러를 보강했습니다.
  • 로그인 없는 상태에서 숫자 ID 기반 코칭 조회 API가 열리지 않도록 제거했습니다.

1. VideoStorage Bean 구현체가 PR에 빠져 있던 문제

P1 처리 완료
문제 .gitignore의 storage/ 규칙이 루트 저장 폴더뿐 아니라 src/.../infrastructure/storage 패키지도 무시했습니다. 그래서 실제 Bean 구현체가 Git에 올라가지 않았습니다.
변경 ignore 대상을 루트의 런타임 폴더로 한정하고, LocalVideoStorage를 추적 대상으로 추가했습니다. 
# .gitignore
/storage/
@Component
public class LocalVideoStorage implements VideoStorage {

    @Override
    public StoredVideo store(Long coachingId, VideoInput video) {
        String storageKey = "coachings/" + coachingId + "/" + storedFilename(video);
        Path destination = root.resolve(storageKey).normalize();
        Files.createDirectories(destination.getParent());
        try (InputStream inputStream = video.openStream()) {
            Files.copy(inputStream, destination, StandardCopyOption.REPLACE_EXISTING);
        }
        return new StoredVideo(storageKey, destination.toUri().toString());
    }
}

3. focus axes 정규화 없이 저장/마이그레이션하던 문제

P1 처리 완료
문제 기존 JSON에 중복 축, null, 빈 문자열이 있으면 새 coaching_focus_axes 테이블의 unique/not null 제약 때문에 Flyway가 실패할 수 있었습니다.
변경 마이그레이션과 도메인 저장 모두에서 순서를 보존하며 trim, null/blank 제거, 중복 제거를 수행하도록 바꿨습니다. 
private List<String> normalizeAxes(List<String> axes) {
    LinkedHashSet<String> normalizedAxes = new LinkedHashSet<>();
    for (String axis : axes) {
        if (axis == null) {
            continue;
        }
        String normalizedAxis = axis.trim();
        if (!normalizedAxis.isBlank()) {
            normalizedAxes.add(normalizedAxis);
        }
    }
    return new ArrayList<>(normalizedAxes);
}

9. application service가 HTTP status를 알던 문제

처리 완료
문제 use case 계층이 HttpStatus와 API 응답 예외를 직접 만들고 있었습니다. 이러면 web adapter 밖에서 재사용하기 어렵습니다.
변경 application 전용 ApplicationException을 만들고, HTTP status 매핑은 global handler로 옮겼습니다. 
public class ApplicationException extends RuntimeException {
    private final String code;
    private final Map<String, Object> details;
}
@ExceptionHandler(ApplicationException.class)
ResponseEntity<ApiErrorEnvelope> handleApplicationException(ApplicationException exception) {
    return ResponseEntity
        .status(statusFor(exception.code()))
        .body(ApiErrorEnvelope.error(exception.code(), exception.getMessage(), exception.details()));
}
