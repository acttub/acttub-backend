SOMA-98 코칭 API 설계

알파 단계 코칭 실행 API 명세입니다. 이 HTML 문서를 현재 스펙의 기준 문서로 사용합니다.

메인 API 코칭 실행

연기 영상을 업로드하고, AI 코칭을 동기 실행한 뒤 입력과 결과를 저장하고 완료 결과를 반환합니다.

후속 API 사용자 평가

완료된 코칭 결과를 확인한 뒤 별점과 선택 코멘트를 한 번 제출합니다.

응답 형식 일관된 응답 구조

성공은 data, 실패는 error를 사용합니다.

저장 MySQL + Flyway

요청 메타데이터, AI 실행 메타데이터, 정규화된 피드백, 실패 정보, 평가를 저장합니다.

범위

POST /api/v1/coachings Content-Type: multipart/form-data

이 API는 연기 영상과 코칭 맥락을 받아 AI 코칭을 동기 실행하고, 입력값과 AI 결과를 데이터베이스에 저장한 뒤 같은 응답에서 완료 결과를 반환합니다.

AI 결과에 대한 사용자 평가는 사용자가 결과를 확인한 뒤 별도 후속 API로 저장합니다.

현재는 로그인과 소유자 검증이 없으므로 저장된 코칭 결과를 ID로 다시 조회하는 공개 API를 제공하지 않습니다.

요청

필드 타입 필수 설명
video file 예 사용자가 업로드한 연기 영상입니다.
performanceIntent string 예 배우가 표현하려고 한 의도입니다.

이 API는 focus category를 받지 않습니다. 코칭 모델이 배우의 의도와 영상 분석 결과를 바탕으로 가장 유용한 단일 focus를 결정합니다.

영상 업로드 정책

  • 프론트엔드는 업로드 전에 영상을 100MB 수준으로 다운스케일/압축하는 것을 권장합니다.
  • 백엔드는 300MB 또는 314572800 bytes를 하드 제한으로 강제합니다.
  • 허용 content type은 video/mp4, video/quicktime, video/webm입니다.
  • 제한을 초과한 업로드는 413 Payload Too Large를 반환합니다.

  • API ID는 데이터베이스에 bigint로 저장되더라도 응답에서는 문자열입니다.
  • 시간값은 offset이 포함된 ISO-8601 문자열입니다. 예: 2026-06-11T10:30:00+09:00

  • 실패 응답은 data를 포함하지 않습니다.
  • error.details는 항상 object입니다. 추가 정보가 없으면 {}를 사용합니다.

성공 흐름

  1. multipart 요청 필드를 검증합니다.
  2. 상태가 ANALYZING인 coaching row를 저장합니다.
  3. 영상 메타데이터와 입력 맥락을 저장합니다.
  4. 요청 안에서 AI 코칭 분석을 동기 실행합니다.
  5. AI 결과와 피드백 카드 필드를 저장합니다.
  6. 코칭 상태를 COMPLETED로 갱신합니다.
  7. 완료된 코칭 결과와 함께 201 Created를 반환합니다.

분석 파이프라인

SOMA-98의 현재 백엔드 구현은 프론트엔드 전용 focus category 입력을 받지 않고, Gemini adapter 뒤에서 영상 업로드와 JSON 분석 요청을 처리합니다.

  1. multipart 요청을 검증합니다.
  2. 상태가 ANALYZING인 coaching row를 먼저 저장합니다.
  3. 업로드된 영상을 VideoStorage 구현체에 저장하고, 저장 key와 URI를 coaching row에 기록합니다.
  4. 설정된 CoachingAnalyzer 구현체를 호출합니다. 기본 구현은 GeminiCoachingAnalyzer입니다.
  5. Gemini adapter는 Files API로 영상을 resumable upload합니다.
  6. 업로드된 파일이 ACTIVE 상태가 될 때까지 polling합니다.
  7. generateContent를 한 번 호출해 정해진 JSON 형식의 코칭 결과를 생성합니다.
  8. provider JSON을 현재 CoachFeedback 구조로 파싱합니다.
  9. AI 결과를 coaching row와 coaching_focus_axes에 저장하고 상태를 COMPLETED로 바꿉니다.

현재 프론트엔드 파이프라인은 category, startTime, endTime도 사용하지만, SOMA-98 백엔드 API는 나중에 명시적으로 추가하지 않는 한 이 필드들을 노출하지 않습니다.

평가 규칙

  • COMPLETED 상태의 coaching만 평가할 수 있습니다.
  • 알파 구현에서는 coaching 하나당 평가를 최대 한 번만 저장할 수 있습니다.
  • rating이 없거나 범위를 벗어나면 400 Bad Request를 반환합니다.
  • 알 수 없는 coachingId는 404 Not Found를 반환합니다.
  • COMPLETED가 아닌 coaching을 평가하면 409 Conflict를 반환합니다.
  • 같은 coaching에 두 번째 평가를 제출하면 409 Conflict를 반환합니다.
  • 평가 응답은 항상 comment를 포함합니다. 사용자가 제공하지 않았으면 null을 사용합니다.

저장

구현은 생성 응답, 실패 추적, 사용자 평가 저장, 나중에 인증 기반 조회를 추가할 수 있도록 충분한 데이터를 저장합니다.

  • Coaching 상태와 시간값

  • 로컬 영상 저장 경로와 URI

  • AI provider, 모델명, temperature, prompt version
  • AI 결과 필드: sceneIntent, strength, focus, nextStep

데이터베이스 스키마

SOMA-98 저장소는 MySQL을 사용합니다. 스키마 변경은 런타임 자동 생성이 아니라 Flyway migration으로 관리합니다. 원본 영상 bytes는 데이터베이스에 저장하지 않습니다.

result_focus_axes JSON 컬럼은 V4에서 제거하고, focus 축 목록은 별도 테이블로 정규화합니다.

coaching_focus_axes

create table coaching_focus_axes (
  coaching_id bigint not null,
  axis_order int not null,
  axis varchar(100) not null,

  constraint pk_coaching_focus_axes
    primary key (coaching_id, axis_order),

  constraint fk_coaching_focus_axes_coaching
    foreign key (coaching_id) references coachings(id),

  constraint uq_coaching_focus_axes_axis
    unique (coaching_id, axis)
);

coaching_evaluations

create table coaching_evaluations (
  id bigint not null auto_increment primary key,
  coaching_id bigint not null,
  rating int not null,
  comment text,
  created_at datetime(6) not null,

  constraint fk_coaching_evaluations_coaching
    foreign key (coaching_id) references coachings(id),

  constraint uq_coaching_evaluations_coaching
    unique (coaching_id),

  constraint chk_coaching_evaluations_rating
    check (rating between 1 and 5)
);

테스트

  • 유효한 multipart 요청은 data.status = COMPLETED와 함께 201 Created를 반환합니다.
  • 성공 응답은 data envelope와 문자열 ID를 사용합니다.
  • 오류 응답은 code, message, object details를 포함한 error envelope를 사용합니다.
  • 필수 필드가 없으면 400 Bad Request를 반환합니다.
  • 업로드 크기 초과는 413 Payload Too Large를 반환합니다.
  • Provider adapter 결과는 동일한 CoachFeedback 응답 구조로 정규화합니다.
  • AI 실패는 502 Bad Gateway를 반환하고 실패한 coaching id를 노출합니다.
  • AI 타임아웃은 504 Gateway Timeout을 반환하고 실패한 coaching id를 노출합니다.
  • 유효한 평가 요청은 data.rating과 함께 201 Created를 반환합니다.
  • 잘못된 rating의 평가는 400 Bad Request를 반환합니다.
  • 알 수 없는 coaching에 대한 평가는 404 Not Found를 반환합니다.
  • COMPLETED가 아닌 coaching에 대한 평가는 409 Conflict를 반환합니다.
  • 같은 coaching에 대한 중복 평가는 409 Conflict를 반환합니다.
